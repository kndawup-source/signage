CLINIC SIGNAGE v2.5 · PIN 전용 로그인 · 30개 진료실 운영형

[구조]
- Supabase: PIN 인증 / 제어 / 환자 맞춤 조건 / 송출 명령 / 플레이어 상태
- 내부 서버 PC: 실제 영상 파일 + 정적 HTML/CSS/JS + HTTP Range 스트리밍
- 환자 화면: 내부 서버 영상을 전체화면 재생
- Supabase Storage에는 영상 파일을 저장하지 않음

1. Supabase + PIN 설정
- Supabase SQL Editor에서 supabase/schema.sql 전체 실행
- 기존 v2.x 데이터는 유지되는 마이그레이션형
- 이메일/비밀번호 계정은 더 이상 로그인에 사용하지 않음
- schema.sql 실행 직후 SQL Editor에서 아래 명령을 1회 실행
  select public.configure_signage_pins('123456','4321');
- 첫 번째 값: 관리자 PIN, 정확히 숫자 6자리
- 두 번째 값: 스텝 PIN, 숫자 4~6자리
- 위 예시 번호를 그대로 사용하지 말고 실제 사용할 번호로 반드시 변경
- PIN은 원문으로 저장되지 않고 pgcrypto bcrypt 해시로 저장
- 초기 설정 후에는 관리자 > 설정 > PIN 관리에서 관리자/스텝 PIN을 변경할 수 있음
- SQL Editor의 configure_signage_pins(...)를 다시 실행해도 둘 다 변경 가능하며 기존 로그인 세션은 모두 종료됨
- 로그인 5회 연속 실패 시 해당 기기에서 5분 잠금
- 로그인 세션 유효시간 12시간, 로그아웃 시 서버 세션도 즉시 폐기

2. 웹 설정
- js/config.js에 Supabase URL / anon key 입력
- 현재 기준값: pollMs 120000 / heartbeatMs 60000 / livePresenceMs 60000 / livePollMs 60000 / onlineThresholdMs 180000

3. 영상 서버 PC
- Node.js LTS 설치
- server/config.example.json -> server/config.json 복사
- 서버 PC 자체 영상폴더 권장: C:\Users\Public\Videos
- 다른 PC에서 파일 복사: \\12F-MSO0\Users\Public\Videos
- server/start-media-server.bat 실행
- TCP 8080 인바운드 허용
- 서버 PC 고정 IP 또는 DHCP 예약
- 서버 PC는 유선 Gigabit LAN + SSD 권장

4. Supabase JS 고정
- v2.5.2는 @supabase/supabase-js 2.118.0으로 고정
- 서버 최초 온라인 실행 때 server/cache/supabase.js로 1회 저장
- 이후 인터넷 장애 시에도 내부 서버가 로컬 파일 제공

5. 영상 등록
- 영상 폴더에 MP4/WebM/M4V 복사
- 관리자 > 영상 관리 > 서버 영상 동기화
- Supabase에는 경로/크기/수정시각/조건만 저장
- 동일 파일명 덮어쓰기도 수정시각 버전값으로 즉시 반영

6. 비상 로컬 영상
- 관리자 > 설정 > 비상 로컬 영상에서 1개 지정
- 권장: 짧은 H.264 MP4, 약 50~200MB
- 비상영상 최대 지정 크기: 250MB
- 각 플레이어가 서버 정상 시 이 파일을 브라우저 로컬 캐시에 미리 저장
- 내부 영상 서버가 끊기면 자동으로 비상영상을 반복 재생
- 서버 복구 감지 후 정상 송출로 자동 복귀
- 환자 PC는 start-player-kiosk.bat로 실행해야 LAN HTTP 주소도 secure context로 취급되어 Cache API/Wake Lock을 안정적으로 사용 가능

7. 환자 맞춤 자동송출
- 영상별 연령 / 성별 / 진료유형 지정
- 스텝 일반 사용: 진료유형 1번 터치
- 세분화 필요: 대상 1번 + 진료유형 1번, 최대 2번
- 우선순위: 전체 송출 > 관리자 개별 송출 > 환자 맞춤 > 기본 영상

8. 전체 동기 송출
- 관리자가 전체 송출 시작 시 DB 서버시각 기준 3초 뒤 effective_at 예약
- 30개 플레이어는 같은 시작시각을 기준으로 재생
- 명령을 늦게 받은 플레이어는 서버시각과 재생 위치를 보정
- 전체 송출 중 영상을 변경하면 새 revision + 새 effective_at으로 다시 동기 시작

9. 실제 송출 상태
- 상태 변경은 즉시 player_report, presence/통계 heartbeat는 60초 기준
- 관리자에는 명령값이 아니라 실제 재생 영상/모드/상태/위치/음소거/오류 표시
- heartbeat JSON은 DB에서 최대 크기 및 허용 필드만 정규화하여 저장

10. 관리자 운영 경고
- 내부 영상 서버 OFFLINE
- 디스크 여유가 설정 기준 이하
- 오프라인 진료실
- 플레이어 재생 오류
- 설정 > 디스크 경고 기준 기본 20GB
- 연결 테스트에서 영상 수 / 디스크 여유 / 현재 스트림 / 고정 Supabase JS 버전 확인

11. 자동 실행
- 서버: server/install-server-startup.bat
- 플레이어: player/install-player-startup.bat
- 플레이어 URL은 player/player-url.example.txt -> player-url.txt 복사 후 입력
- start-player-kiosk.bat는 kiosk / autoplay / secure-origin 옵션을 자동 적용
- Windows AC 화면꺼짐/절전/최대절전 비활성화

12. 30개 진료실 기준
- HTTP server maxConnections 200
- 영상은 HTTP Range Streaming
- 영상 전체를 서버 RAM에 적재하지 않음
- 1080p H.264 4~6Mbps × 30실 = 약 120~180Mbps 수준
- 서버 및 스위치는 Gigabit 유선 권장
- 30실 전체를 Wi-Fi만으로 운영하는 것은 권장하지 않음

13. 장애 시 동작
- 관리자/스태프 상태 보정: 화면이 보일 때 60초 변경분 조회 + 제어 직후 해당 공간 ACK
- Supabase 일시 장애: 열린 플레이어는 마지막 상태 유지
- 영상 서버 장애: 현재 플레이리스트 1회 확인 후 로컬 비상영상 전환
- 서버 복구: 15초 간격 확인 후 정상 영상 자동 복귀
- 전체송출 영상 삭제/비활성: 개별 > 맞춤 > 기본으로 fallback
- 폴더에서 영상 삭제: 동기화 후 available=false

14. 보안
- 8080 인터넷 포트포워딩 금지
- player_key URL 외부 공유 금지
- staff는 player_key 원본 조회 불가
- heartbeat는 허용 필드/크기 제한 후 저장

16. v2.5 PIN 로그인
- 로그인 화면에는 이메일/비밀번호가 없고 PIN 입력만 표시
- PIN 값에 따라 ADMIN / STAFF 권한 자동 판별 후 해당 화면으로 이동
- PIN 원문은 js/config.js, HTML, localStorage에 저장하지 않음
- 브라우저에는 12시간짜리 임의 세션 토큰만 저장
- RLS는 Supabase Auth 이메일 계정이 아니라 PIN 세션 헤더를 검증
- 관리자/스태프 상태 화면은 테이블 Realtime 구독 대신 60초 변경분 조회와 제어 직후 공간별 ACK를 사용
- 전체/개별 송출 명령은 기존 realtime.send 경로를 그대로 사용하므로 플레이어 전환 속도에는 영향 없음

[v2.6 그룹/공간 운영]
- 관리자 > 공간 / 그룹에서 10F, 11F, 12F, 상담실, 대기실, VIP 등 그룹을 자유롭게 만듭니다.
- 공간 유형은 진료실 / 상담실 / 대기실 / 기타 중 선택합니다.
- 진료실·상담실: 스텝 환자 맞춤 송출 사용 가능.
- 대기실: 환자 맞춤 없이 전체/그룹/기본 송출 중심.
- 송출 우선순위: 전체 병원 > 전체 예약 > 개별 공간 > 층·구역 > 그룹 예약 > 환자 맞춤 > 기본.
- 대시보드에서 여러 공간을 체크해 한 번에 송출/자동복귀할 수 있습니다.
- 전체 병원/그룹 예약 송출과 최근 제어 이력의 직전 상태 복귀를 지원합니다.
- 전체 송출 종료 시 '이전 상태' 또는 '모두 기본영상'을 선택할 수 있습니다.

[v2.29.0 CANONICAL DEPLOY]
- DB는 Supabase SQL Editor에서 supabase/schema.sql 하나만 실행합니다. 신규/기존 환경 모두 재실행 안전성을 기준으로 작성되어 있습니다.
- 과거 버전별 SQL 파일은 이력/참조용입니다. 최신 배포에 순차 실행하지 않습니다.
- player_report / signage_live_status / player_control_signals / signal_signage_rooms / frame-presence 기반 ACK 구조를 유지합니다.
- 관리자/스텝 상태 조회는 화면이 보일 때 60초마다 변경분만 조회합니다. 5초/10초 전체 polling은 사용하지 않습니다.
- 제어 직후 ACK는 영향을 받은 공간만 짧게 확인하고 완료 시 즉시 종료합니다.

OPERATING HOURS
- 관리자 설정에서 평일 / 토요일 / 일요일 반복 운영시간을 지정합니다.
- 공간별로 전체 기본 운영시간을 따르거나 별도 운영시간을 사용할 수 있습니다.
- 운영시간 밖에는 검정 화면 저활동 모드로 전환합니다: 영상/preload/cache refresh/statistics 중지, presence/heartbeat 저빈도.
- 다음 정상 시작시간에는 next_transition_at 타이머 또는 Realtime/포커스 복구로 자동 재개합니다.
- 송출 현황의 '오늘 운영 종료'는 당일 남은 송출을 즉시 종료하고 다음 정상 운영 시작시간에 자동 복귀합니다.

PLAYER / OFFLINE CACHE
- 브라우저 Cache Storage에 현재 플레이리스트를 백그라운드 저장합니다.
- 관리자 카드 표시: 준비 완료 x/x / 캐시 부족 x/x / 오프라인 재생 중 x/x / 캐시 오류.
- 운영시간 외에는 캐시 갱신을 시작하지 않습니다. 이미 운영 종료 상태를 받은 플레이어는 네트워크가 끊겨도 캐시 영상을 임의 재생하지 않습니다.
- Windows player/start-player-kiosk.bat는 Chrome 종료 시 5초 후 재실행하며, install-player-startup.bat로 로그인 자동실행을 등록합니다.

VIDEO STANDARD
- 업로드 허용: .mp4 / video/mp4.
- 등록 전 브라우저 재생 가능 여부, H.264(avc1/avc3), AAC(mp4a), duration, 해상도, 파일 크기를 확인합니다.
- 2GB 초과, 2시간 초과, 4K 초과, 코덱 기준 미충족은 R2 업로드 전에 차단합니다. 저해상도는 관리자 화면에 경고 상태로 저장합니다.

STATUS / PRIORITY
- 사용자-facing 상태는 송출 중 / 대기 / 오프라인 / 오류 / 업데이트 필요로 통일합니다.
- 문제 공간은 관리자/스텝 카드에서 우선 표시할 수 있으며 관리자는 '문제 공간만 보기'를 사용할 수 있습니다.
- 카드에 현재 송출 우선순위(전체 / 예약 / 개별 / 층·구역 / 기본 등)를 표시합니다.

LOG RETENTION
- player_events 상태 이벤트: 30일 보관 후 관리자 화면 진입 시 일 1회 정리합니다.
- room_playback_daily 재생 통계: 장기 보관합니다.
- heartbeat 자체를 raw 로그로 누적하지 않고 상태 변화만 player_events에 기록합니다.
