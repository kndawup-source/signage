CLINIC SIGNAGE v2.34.9 · CANONICAL SETUP

[역할]
- SUPER ADMIN: /admin.html
  전체 병원 현황, 병원 생성, 활성화/비활성화/삭제, 병원 관리자 PIN, 병원 설정 백업/복원, 로그 정리
- HOSPITAL ADMIN: /hospital.html?site=병원슬러그
  자기 병원 송출/플레이리스트/운영시간/층/도면/공간/디스플레이 관리
- PATIENT DISPLAY: /player.html?key=디스플레이키

[신규 Supabase 설치]
1. supabase/schema.sql 전체 실행
2. 결과 오류가 없는지 확인
3. 프런트/서버 파일 배포
4. /admin.html 에서 첫 병원 생성 + 병원 관리자 PIN 지정
5. 병원 관리자 페이지에서 층 → 디스플레이 → 도면/위치 순으로 설정

[기존 v2.34.x 운영 DB 업그레이드]
1. DB 백업
2. supabase/v2.34.9-site-lifecycle.sql 1회 실행
3. 프런트/서버 v2.34.9 배포
4. 관리자/플레이어 강력 새로고침
5. 아래 검수 진행

[중요]
- supabase/v2.33.22-player-state-rpc-restore.sql 은 폐기되었습니다. 실행하지 마세요.
- 이전 버전 SQL을 장애 대응용으로 다시 실행하지 마세요. v2.34.9 이후에는 canonical schema 또는 현재 버전 migration만 사용합니다.
- schema_version 테이블에서 v2.34.9 적용 여부를 확인할 수 있습니다.

[출시 전 검수]
1. A병원 기본 플레이리스트 지정 → A병원 TV에서 재생되는지
2. B병원에 영향이 없는지
3. 잘못된 운영시간 값은 저장 RPC에서 거절되는지
4. 오늘 송출 종료 후 운영시간 저장 → 조기 종료 상태가 유지되는지
5. 병원 관리자 계정으로 다른 병원 URL 접근이 차단되는지
6. 새 병원 생성 시 PIN 설정 후 즉시 로그인 가능한지
7. 병원 관리자에서 새 층/새 디스플레이를 만들 수 있는지
8. 환자 화면 링크가 정상 동작하는지

[운영시간]
- 저장은 hospital_save_operating_config RPC만 사용합니다.
- site_settings 직접 INSERT/UPDATE/DELETE 권한은 제거되었습니다.
- HH:MM 형식이 아닌 값은 저장되지 않습니다.
- 저장된 설정이 손상돼도 player 상태 계산은 기본 운영시간으로 fail-safe 처리합니다.

[기본 플레이리스트]
- 디스플레이/층에 별도 플레이리스트가 없으면 해당 병원의 kind=default 플레이리스트를 공용 default보다 우선합니다.
- 병원 default가 없을 때만 공용 default를 사용합니다.

[병원 생성/상태]
- SUPER ADMIN > 병원 추가에서 병원명, 고유 주소, 병원 관리자 PIN을 함께 지정합니다.
- 고유 주소가 중복되면 새 병원으로 처리하지 않습니다.
- 비활성화하면 해당 병원 관리자 로그인 세션이 종료되고 환자 화면 송출이 중지됩니다.
- 비활성 병원은 다시 활성화할 수 있습니다.
- 삭제는 비활성 병원에서만 가능하며 병원명을 직접 입력해야 합니다. 병원 소속 DB 데이터와 병원 전용 도면 R2 파일을 함께 정리합니다.

[층/디스플레이 생성]
- HOSPITAL ADMIN > 설정 > 공간·도면·디스플레이 설정에서 생성합니다.
- 층: 1~99
- 디스플레이 운영방식: REMOTE / MANUAL / HYBRID

[도면]
- PNG/JPG/WebP, 최대 12MB
- 기본/하드코딩 도면 없음
- 업로드된 도면이 없으면 '도면 없음'으로 표시
- 도면 URL은 PIN 세션 검증을 거쳐 발급

[배포 제외]
.vercelignore에서 supabase/, SETUP.txt, QA 문서, 구 도면/서버 폴더를 배포에서 제외합니다.

[영상]
- 이 제품에서는 영상 파일 업로드 UI를 제공하지 않습니다.
- 이미 등록된 영상 자산을 병원별 플레이리스트에 연결해 사용합니다.

[플레이어]
- Fast boot로 첫 영상을 우선 재생합니다.
- 저장된 마지막 상태가 운영시간이 끝난 상태라면 fast boot에서 재생하지 않습니다.
- player-fastboot.js는 Service Worker shell cache에 포함됩니다.

[로그]
- 슈퍼어드민 병원 요약 > 관리 도구에서 오래된 player_events를 정리할 수 있습니다.
- 개인정보가 포함될 수 있는 patient_sessions 보관기간은 병원 정책에 맞춰 별도로 결정하세요.
