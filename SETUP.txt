CLINIC SIGNAGE v2.33.20 · SUPER ADMIN / HOSPITAL ADMIN / PATIENT DISPLAY

[배포 순서]
1. 기존 v2.32.3 운영 DB라면 Supabase SQL Editor에서 아래 파일을 1회 실행
   supabase/v2.33.0-product-foundation.sql
2. 신규 설치 또는 전체 canonical 재구축은
   supabase/schema.sql
   하나를 실행
3. 프런트/서버 파일 배포
4. 관리자 페이지 강력 새로고침

README는 사용하지 않습니다.

[권한]
- SUPER ADMIN (/admin.html)
  전체 병원/지점, 도면, 공간, 디스플레이, 공용 콘텐츠, 상태, 백업/감사 관리
- HOSPITAL ADMIN (/hospital.html?site=병원슬러그)
  자신의 병원만 조회/수정. 병원명, 도면, 공간 구분, 디스플레이 위치/운영방식, 병원 전용 플레이리스트 관리
- PATIENT DISPLAY (/player.html?key=디스플레이키)
  실제 REMOTE/HYBRID 디스플레이에서 환자가 보는 영상 화면

[기존 단일 병원 호환]
- migration 실행 시 현재 운영 데이터는 자동으로 default site에 연결됩니다.
- 기존 영상/플레이리스트는 site_id=NULL인 공용 콘텐츠로 유지됩니다.
- 기존 player_key, player_report, signage_live_status, player_control_signals, ACK, frame presence, offline cache, timed output은 유지됩니다.
- player release는 기존 2.30.0을 유지합니다. 이번 버전은 운영/관리 계층 확장입니다.

[병원 추가]
- SUPER ADMIN > 설정 > 병원 / 지점에서 추가
- 각 병원은 고유 Hospital Admin PIN을 사용합니다.
- PIN 로그인 화면은 하나이며 PIN으로 병원을 식별합니다.
- 다른 병원에서 이미 사용 중인 Hospital Admin PIN은 사용할 수 없습니다.

[초기 설치 권장 흐름]
1. 병원명 / 건물명
2. 층/구역 생성
3. 층별 도면 업로드
4. 도면 위에서 공간 영역 드래그 지정
5. 디스플레이 운영 방식 지정
   REMOTE / MANUAL / HYBRID
6. 도면 클릭으로 디스플레이 위치 점 배치
7. 병원/공용 플레이리스트 연결

[도면]
- PNG / JPG / WebP, 층별 최대 12MB
- 모든 층은 동일한 가로형 1440×632 작업 캔버스로 표시됩니다.
- 업로드 이미지는 contain 방식으로 왜곡 없이 들어갑니다.
- 기본 제공 진료층 도면: 3F / 7F / 8F / 9F / 10F는 같은 3F 진료층 구조를 공유합니다.
- 4F는 별도 진료층 도면입니다.
- 사용자 업로드 도면은 해당 층만 덮어씁니다.
- 층별 최근 5개 업로드 버전을 보관하며 이전 버전으로 복원할 수 있습니다.
- 오래된 비활성 버전은 R2에서 자동 정리합니다.
- 도면 URL은 PIN 세션 검증을 거치는 /api/floorplan을 통해서만 제공합니다.

[공간 구분]
- 도면은 배경입니다. 시스템이 공간을 임의 추정하지 않습니다.
- 관리자가 도면 위에서 사각형/직사각형으로 필요한 공간만 직접 지정합니다.
- 공간 유형: 진료실 / 상담실 / 대기 / 라운지 / 접수·안내 / 로비 / 스탭 / 지원 / 공용 / 기타

[디스플레이 위치]
- 자동/임의 위치 생성 없음
- 설정에서 디스플레이를 선택하고 도면을 클릭하면 점으로 저장됩니다.
- 저장된 점은 드래그로 재배치할 수 있습니다.
- 위치 지우기 시 map_x_pct / map_y_pct는 NULL로 초기화됩니다.

[디스플레이 운영 방식]
REMOTE
- 중앙 송출 제어 가능
- heartbeat / ACK / offline cache / update / 재생 오류 상태 관리

MANUAL
- 현장에서 USB/로컬 등으로 직접 운영
- heartbeat/ACK/오프라인 판정 대상이 아님
- 수동 운영 / 수동 확인 필요 / 확인 완료 상태로 관리
- 중앙 플레이어 URL이 남아 있어도 서버에서 검정 대기(closed) 상태를 반환해 원격 송출하지 않음

HYBRID
- 원격 송출 가능 + 현장 수동 운영 가능
- 원격 연결 상태와 중앙 제어를 유지

[병원 전용 플레이리스트]
- Hospital Admin은 SUPER ADMIN이 제공한 공용 영상 또는 자기 병원 범위 영상을 조합해 병원 전용 플레이리스트를 만들 수 있습니다.
- 다른 병원의 site playlist는 조회/수정할 수 없습니다.
- 공용 콘텐츠는 site_id=NULL, 병원 전용 콘텐츠/플레이리스트는 site_id=<병원 UUID> 구조입니다.

[실시간 상태 / 부하]
- Realtime wake-up + 해당 room만 즉시 갱신
- 관리자/병원 관리자 변경분 안전망은 최소 30초
- 플레이어 상태 fallback은 운영 중 최소 60초
- 운영시간 외 플레이어 fallback은 10분
- 5초/10초 전체 DB polling 없음
- 플레이어의 10초 watchdog은 로컬 영상 정체 감지이며 DB polling이 아닙니다.

[수동 디스플레이와 통계]
- MANUAL 디스플레이는 player playback 통계와 online/offline 통계에서 제외됩니다.
- REMOTE/HYBRID만 admin_playback_today / admin_building_period_stats의 재생률 대상입니다.
- 수동 점검 완료 여부는 별도로 기록합니다.

[보안 / site scope]
- Hospital Admin의 조회/제어 RPC는 자신의 site_id로 제한됩니다.
- 다른 병원의 room UUID를 직접 넣어도 조작되지 않습니다.
- MANUAL room은 원격 환자 배정/플레이리스트/영상 추가/Realtime signal 대상에서 제외됩니다.
- player_key는 bearer credential이므로 외부 공유 금지
- R2 도면 object key는 site별 경로로 분리됩니다.

[감사 로그]
- 도면/공간/디스플레이/병원 설정/병원 관리자 PIN/수동 확인 등 사람의 설정 변경을 audit_log에 기록합니다.
- heartbeat raw 로그는 감사 로그에 넣지 않습니다.
- player_events 상태 이벤트는 30일 정책, room_playback_daily는 장기 보관을 유지합니다.

[백업]
- SUPER ADMIN 설정에서 현재 병원 설정 JSON 내보내기/복원 가능
- 병원 기본정보, 도면 active pointer, 층/공간, 디스플레이 위치/운영방식 등 운영 설정을 복원합니다.
- player_key를 재발급하거나 플레이어를 교체하지 않습니다.

[Supabase JS]
- document.write 로더를 사용하지 않습니다.
- HTTPS/Vercel: boot.js가 @supabase/supabase-js 2.118.0 고정 CDN을 Promise 방식으로 로드
- 내부 HTTP: /vendor/supabase.js 로컬 캐시 사용

[운영시간 / 캐시]
- 기존 평일/토요일/일요일 반복 운영시간, 공간별 override, 오늘 운영 종료, 저활동 모드 유지
- 운영시간 밖: 검정 대기 / 영상·preload·cache refresh·재생통계 중지 / 저빈도 presence
- 다음 정상 시작시간 자동 재개
- offline cache: 준비 완료 x/x / 캐시 부족 / 오프라인 재생 중 / 캐시 오류 표시

[영상 표준]
- MP4 / H.264 / AAC 기준
- duration / 해상도 / 파일 크기 검사
- 2GB 초과 / 2시간 초과 / 4K 초과 / 기준 코덱 미충족은 등록 전 차단
- 저해상도는 경고
- 반복 재생 실패 영상은 자동 건너뛰며 전체 플레이리스트는 계속 진행
